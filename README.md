# RAG — база знаний Хабра

[English](README.en.md)

Настольное приложение на C++ и Qt 6. Оно ищет ответ в локальной базе вопросов с Хабра и показывает шаги поиска рядом с ответом. Генерация и эмбеддинги идут через два локальных процесса [llama.cpp](https://github.com/ggml-org/llama.cpp) `llama-server`, без Ollama и без облачного ключа.

## Что видно в окне

- **Диалог.** Слева вопрос и ответ, справа журнал шагов: формулировки multi-query, оценки FAISS, полнотекст, слияние, rerank и промпт, который ушёл в модель. Под ответом — время и имена включённых режимов.
- **Настройки.** Адреса серверов, режим без RAG, три приёма поиска, число кандидатов и чанков в промпте, импорт `questions.jsonl`.

База SQLite и файл индекса лежат в каталоге `data` рядом с exe.

## Серверы

Нужны два процесса. Один и тот же `llama-server` не отдаёт и чат, и эмбеддинги.

| Порт | Назначение | Пример |
| --- | --- | --- |
| 8080 | Чат, instruct-модель без LoRA | `llama-server -m qwen2.5-3b-instruct-q4_k_m.gguf --host 127.0.0.1 --port 8080 -c 4096 -ngl 8` |
| 8081 | Эмбеддинги, отдельная embedding-модель | `llama-server -m user-bge-m3-q8_0.gguf --host 127.0.0.1 --port 8081 --embeddings --pooling cls -c 2048 -ngl 99` |

Для русского поиска на 8081 нужна модель, обученная как эмбеддер. В проекте проверялся `USER-bge-m3` (1024 измерения, пул `cls`). Обычная instruct-модель с `--pooling mean` почти не различает чанки. После смены эмбеддера базу надо очистить и импортировать заново: размерность индекса фиксируется первым вектором.

## Режимы

Пока включён RAG, вопрос всегда эмбеддится и ищется в FAISS (`IndexFlatIP` по L2-нормированным векторам). Три галочки добавляют шаги поверх этого поиска.

- **Multi-query.** Модель дописывает ровно два коротких запроса на русском. Строки без кириллицы или с иероглифами отбрасываются.
- **Hybrid search.** К векторному списку добавляется SQLite FTS5, списки сливаются через Reciprocal Rank Fusion.
- **Rerank.** Модель заново упорядочивает найденные чанки.
- **Без RAG.** Вопрос уходит на порт 8080 как есть, без базы и без эмбеддинга.

Импорт читает JSON Lines с полями Хабра (`title`, HTML в `description` и `answers[].body`), режет ответы на чанки и не очищает базу сам. Повторный импорт тех же вопросов создаёт копии. Файл `questions.jsonl` в репозиторий не входит.

## Сборка

Windows, CMake 3.21+, Qt 6.5 (Core, Gui, Widgets, Sql, Network), компилятор MSVC с OpenMP. Подмножество FAISS 1.7.4 и библиотеки OpenBLAS лежат в `third_party` и собираются вместе с приложением.

В Qt Creator откройте `CMakeLists.txt` и соберите цель `RAG`. Либо из командной строки, из окружения Visual Studio:

```bat
cmake -S . -B build -DCMAKE_PREFIX_PATH=C:/Qt/6.11.1/msvc2022_64
cmake --build build --config Release
```

Путь к Qt замените на свой. Рядом с exe должна оказаться `openblas.dll`: шаг POST_BUILD копирует её сам.
